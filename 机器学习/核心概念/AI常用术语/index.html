AI常用术语

发表于2026-08-08|更新于2026-08-09|机器学习核心概念

1. AI 与模型基础

AI（Artificial Intelligence，人工智能）

让机器完成通常需要人类智能的任务，例如感知、理解、预测、规划和决策。AI 是一个宽泛领域，不要求机器以和人类相同的方式思考。

ML（Machine Learning，机器学习）

让模型从数据中学习规律，而不是由开发者写出覆盖所有情况的固定规则。监督学习、无监督学习和强化学习都属于机器学习。

DL（Deep Learning，深度学习）

使用多层神经网络学习表示和任务映射，是现代视觉、语音和语言模型的重要技术基础。

AGI（Artificial General Intelligence，人工通用智能）

通常指能够跨领域学习、迁移和完成广泛认知任务的通用智能。AGI 尚无统一、可操作的行业判定标准，不宜简单等同于“参数很大的模型”。

Narrow AI（专用人工智能）

针对特定任务设计或训练的系统，例如人脸识别、广告点击率预估。它可以在单项任务上表现很强，但不代表具备通用能力。

Model（模型）

由结构、参数和计算规则构成的函数。训练负责调整参数，推理负责使用已训练参数生成预测或内容。

Parameter（参数）

模型训练过程中学习到的数值，例如神经网络权重。参数量会影响模型容量和存储成本，但不能单独决定能力。

Hyperparameter（超参数）

由训练者设定而不是直接从数据中学到的配置，例如学习率、批大小、层数和权重衰减。

Foundation Model（基础模型）

在大规模数据上预训练、可适配多个下游任务的模型。大语言模型、多模态模型都可以是基础模型。

Generative AI（生成式 AI）

学习数据分布并生成新内容的 AI，可输出文本、图像、音频、视频或代码。它与只输出类别或分数的判别式模型关注点不同。

2. 生成模型与经典架构

GAN（Generative Adversarial Network，生成对抗网络）

由生成器和判别器对抗训练：生成器尝试产生逼真样本，判别器判断样本来自真实数据还是生成器。GAN 生成锐利图像的能力较强，但训练可能不稳定并出现模式崩溃。

VAE（Variational Autoencoder，变分自编码器）

把输入编码为潜变量分布，再从潜变量采样并解码重建数据。VAE 的潜空间连续、便于采样和插值，但传统 VAE 的图像可能偏平滑。

Diffusion Model（扩散模型）

训练模型逐步去除噪声，把随机噪声还原为数据样本。许多图像和视频生成系统使用扩散或相关流模型。

Autoregressive Model（自回归模型）

按顺序预测下一个元素，并把已经生成的内容作为后续条件。对文本序列 x1:Tx_{1:T}x1:T​，联合概率可分解为：

GPT 是典型自回归语言模型。

Transformer

以 Attention 为核心的序列建模架构。Self-Attention 负责位置之间的信息交互，FFN 负责每个位置内部的特征变换。

Attention（注意力机制）

MoE（Mixture of Experts，混合专家）

模型包含多个专家网络，路由器为每个 Token 选择少量专家参与计算。MoE 可在不让每个 Token 激活全部参数的情况下扩大模型容量，但会增加路由、负载均衡和分布式通信的难度。

Multimodal Model（多模态模型）

同时处理文本、图像、音频、视频等多种模态的模型。多模态并不只表示“能接收图片”，还涉及不同模态表示的对齐与融合。

3. LLM、Token 与上下文

LLM（Large Language Model，大语言模型）

在大规模文本或多模态数据上训练的语言模型，能够基于上下文预测 Token，并由此完成生成、问答、摘要和代码等任务。

GPT（Generative Pre-trained Transformer）

生成式预训练 Transformer。Generative 表示生成式建模，Pre-trained 表示先在大规模数据上预训练，Transformer 表示核心网络架构。

Token（词元）

模型处理文本的基本单位，可以是字符、子词、标点、数字或字节片段。一个 Token 不固定等于一个汉字或一个英文单词，具体切分取决于 Tokenizer 和词表。

Tokenization（分词 / 词元化）

把文本转换为 Token ID 序列的过程。模型实际接收的是这些 ID 对应的向量，而不是原始字符串。

Tokenizer（分词器）

执行文本规范化、切分以及 Token 与 ID 互转的组件。模型必须配套使用训练时的 Tokenizer，否则输入含义会错位。

BPE（Byte Pair Encoding，字节对编码）

一种常见的子词词表构建方法，反复合并高频相邻单元，使常见片段成为完整 Token，少见词仍可拆分表示。不同 LLM 可能使用 BPE、字节级 BPE、Unigram 等不同方案，不能把 BPE 当成所有模型的唯一选择。

Vocabulary（词表）

Tokenizer 可识别的 Token 集合。词表越大，某些文本需要的 Token 数可能越少，但 Embedding 和输出层也会变大。

Embedding（嵌入）

把离散 Token ID 映射为连续向量。Embedding 的几何关系由训练目标塑造，不是人工预先规定的词典解释。

Context Window（上下文窗口）

模型一次推理能够处理的 Token 范围，通常包含系统指令、用户输入、历史消息、工具结果和生成内容。窗口长度是 Token 数，不是字符数。

Prompt（提示词）

提供给模型的输入，可以包含任务、背景、约束、示例和输出格式。Prompt 不是魔法口令，信息是否充分、是否互相冲突通常比堆砌技巧更重要。

Prompt Engineering（提示词工程）

设计、测试和迭代 Prompt，以提高模型输出的正确性、稳定性和可控性。Prompt 读作 /prɒmpt/，不要与 promote 混淆。

In-Context Learning（上下文学习）

模型仅通过当前输入中的说明或示例适应任务，不更新模型参数。Zero-shot、One-shot 和 Few-shot 分别表示不给示例、给一个示例和给少量示例。

Hallucination（幻觉）

模型生成了看似合理但缺乏依据、与事实或输入冲突的内容。检索、工具调用和验证可以降低风险，但不能保证完全消除。

4. 预训练、微调与对齐

Pre-training（预训练）

在大规模数据上学习通用模式。自回归 LLM 通常以预测下一个 Token 为核心目标。

Fine-Tuning（微调）

在预训练模型基础上继续训练，使模型适配任务、领域或行为要求。Fine-Tuning 是上位概念，SFT、指令微调和参数高效微调都属于它的具体做法。

SFT（Supervised Fine-Tuning，监督微调）

使用带有目标输出的监督样本继续训练模型。样本可以是问答、摘要、分类、代码或多轮对话，不要求每条数据都写成自然语言指令。

Instruction Fine-Tuning（指令微调）

使用“指令或对话输入—期望回答”形式的数据做监督微调，目标是让模型理解并遵循自然语言任务。因此，指令微调通常是 SFT 的一个子集；SFT 的数据形式更宽，二者并非互斥训练阶段。

PEFT（Parameter-Efficient Fine-Tuning，参数高效微调）

冻结大部分基础参数，只训练少量新增或选定参数，从而降低显存、存储和多任务部署成本。

LoRA（Low-Rank Adaptation，低秩适配）

用低秩矩阵近似权重更新，在不直接训练完整权重矩阵的情况下适配模型，是常见的 PEFT 方法。

Alignment（对齐）

让模型行为更符合人类意图、安全约束和产品目标。对齐不是单一算法，可涉及 SFT、偏好学习、强化学习、规则和评测。

Preference Data（偏好数据）

对于同一输入，记录哪个回答更好，或为回答给出等级、分数。它可以来自人工标注、规则、模型评审或可验证结果。

Reward Model（奖励模型）

根据输入和回答输出奖励分数，用于近似人类偏好或任务目标。奖励模型可能被策略钻空子，因此需要持续检查 Reward Hacking。

RLHF（Reinforcement Learning from Human Feedback）

利用人类反馈构造奖励或偏好信号，再优化语言模型行为的一类方法。经典流程可包含 SFT、奖励模型训练和强化学习，但实际实现不只一种。

RLAIF（Reinforcement Learning from AI Feedback）

使用 AI 评审生成偏好或奖励信号，再进行策略优化。它能扩大反馈规模，但评审模型的偏差也会被带入训练。

DPO（Direct Preference Optimization，直接偏好优化）

直接利用成对偏好数据优化策略相对参考模型的概率，不显式训练奖励模型，也不需要在线强化学习 rollout。DPO 属于偏好优化方法，不应简单等同于 RLHF 的 PPO 阶段。

5. LLM 强化学习与 Rollout

Policy（策略）

在 LLM 强化学习中，策略通常就是待训练的语言模型。给定 Prompt 和已生成 Token，策略给出下一个 Token 的概率分布。

Action（动作）

最细粒度下，生成一个 Token 就是一次动作；在更高层的 Agent 环境中，一次工具调用或一段完整回答也可能被视为动作。

State（状态）

模型做决策时可见的信息，通常包含 Prompt、已经生成的 Token，以及 Agent 场景中的环境观察和工具结果。

Reward（奖励）

评价回答或轨迹质量的数值信号，可以来自奖励模型、规则验证器、单元测试、数学答案检查或人工反馈。

Return（回报）

从某个时间步开始累计得到的折扣奖励。若 LLM 只在回答结束后获得一个序列级奖励，则这一个结果需要向前影响整段生成中的动作。

Rollout（轨迹采样）

Rollout 指让当前或指定策略从初始状态开始，持续采样动作直到终止，从而得到一条完整或截断轨迹。在纯文本 LLM 训练中，给定一个 Prompt，模型生成一段回答并获得奖励，就构成一条最简单的 rollout；对同一 Prompt 采样多个回答，就得到多条 rollouts。

训练通常会保存 Prompt、生成 Token、对应的对数概率和奖励；Agent 场景还会包含工具结果等环境观察。Response 只强调输出内容，trajectory 强调状态、动作和奖励的序列，episode 则表示从环境重置到终止的一次完整交互。Rollout 更强调按策略向前采样的过程，也常指采样得到的轨迹。

采样多条 rollout 可以比较不同回答的质量并计算训练信号，但生成过程开销较大，常是 LLM 强化学习的主要性能瓶颈之一。

On-Policy / Off-Policy（在策略 / 离策略）

On-policy 方法使用当前策略生成 rollout 并更新当前策略，数据新鲜但生成成本高。Off-policy 方法可以复用旧策略或其他策略产生的数据，样本效率更高，但要处理策略分布不一致。

Advantage（优势函数）

衡量某个动作或回答相对基准表现得有多好。策略梯度通常增加正优势动作的概率，降低负优势动作的概率。

PPO（Proximal Policy Optimization，近端策略优化）

通过裁剪等机制限制每次策略更新幅度，避免新策略偏离旧策略过多。LLM 对齐中常配合奖励模型、价值模型和 KL 约束使用。

GRPO（Group Relative Policy Optimization，组相对策略优化）

对同一 Prompt 采样一组回答，根据组内奖励的相对水平计算优势，再优化策略。它不依赖与 PPO 相同形式的独立价值模型，因此能减少一部分训练成本。

若一组 rollout 的奖励为 r1,…,rGr_1,\ldots,r_Gr1​,…,rG​，常见的组内标准化优势可以写成：

Ai=ri−mean⁡(r1,…,rG)std⁡(r1,…,rG)+ϵA_i=\frac{r_i-\operatorname{mean}(r_1,\ldots,r_G)}{\operatorname{std}(r_1,\ldots,r_G)+\epsilon} Ai​=std(r1​,…,rG​)+ϵri​−mean(r1​,…,rG​)​

“组内比较”并不等于只看名次，具体实现还可能包含裁剪、KL 正则、Token 级损失和不同的优势估计方式。

KL Penalty（KL 惩罚）

限制训练策略与参考策略差异，避免模型为了高奖励过度偏离原有语言能力。约束太强会学不动，太弱则可能产生奖励投机或输出退化。

Reward Hacking（奖励投机）

模型找到奖励函数的漏洞，获得高分却没有真正完成任务。例如通过固定格式、冗长输出或验证器缺陷骗取奖励。

6. 推理与生成

Inference（推理）

使用训练完成的模型对输入生成结果。LLM 推理通常分为 Prefill 和 Decode 两个阶段。

Prefill（预填充）

并行处理输入 Prompt，计算各层表示并建立 KV Cache。长上下文请求的 Prefill 计算量较大。

Decode（解码）

利用已有 KV Cache 逐 Token 生成输出。自回归依赖决定了 Token 之间通常不能完全并行。

KV Cache

缓存 Attention 中历史 Token 的 Key 和 Value，避免每生成一个新 Token 都重新计算完整前缀。它用显存换取解码速度。

Temperature（温度）

调整采样概率分布的平坦程度。温度低时输出更集中，温度高时更多样，但它不等于“事实准确度开关”。

Top-k / Top-p Sampling

Top-k 只在概率最高的 kkk 个 Token 中采样；Top-p 选择累计概率达到阈值 ppp 的最小候选集合再采样。

Greedy Decoding（贪心解码）

每一步选择概率最高的 Token，结果较确定，但局部最优不保证整段序列最好。

Beam Search（束搜索）

同时保留若干高分候选序列继续扩展，常用于翻译等任务。开放式对话中它可能产生重复或过于保守的文本。

Quantization（量化）

用更低精度表示权重或激活，以减少显存、带宽和计算成本。量化位数越低，越需要评估精度损失和硬件支持。

Distillation（知识蒸馏）

让较小的学生模型学习较大教师模型的输出分布、表示或生成数据，从而压缩模型或迁移能力。

7. RAG 与知识增强

RAG（Retrieval-Augmented Generation，检索增强生成）

先从外部知识库检索相关内容，再把结果作为上下文交给生成模型。RAG 可以提高答案的时效性和可追溯性，但检索错误、切分不当和上下文冲突仍会影响结果。

Corpus（语料库）

用于检索的一组文档或数据。语料的权限、版本、质量和更新时间决定了 RAG 能回答什么。

Chunking（分块）

把长文档切成适合索引和输入模型的小块。块太小容易丢上下文，太大则会引入噪声并消耗上下文窗口。

Vector Database（向量数据库）

存储 Embedding 并支持相似向量检索的系统。它通常还提供元数据过滤、索引构建和更新能力。

Dense Retrieval（稠密检索）

用向量相似度匹配 Query 和文档，擅长语义近似；Sparse Retrieval（稀疏检索）则依赖词项匹配，例如 BM25。

Hybrid Search（混合检索）

融合稀疏检索和稠密检索，兼顾关键词精确匹配与语义召回。

Reranker（重排器）

对初步召回的文档进行更精细的相关性打分，再选择少量结果放入 LLM 上下文。

Grounding（依据约束 / 事实落地）

要求模型回答基于给定来源、环境状态或工具结果。Grounding 能减少无依据生成，但仍需检查引用是否真正支持结论。

8. Agent、工具与上下文工程

Agent（智能体）

以模型为决策核心，能够观察环境、规划步骤、调用工具并根据结果继续行动的系统。一次模型调用不自动构成 Agent，关键在于闭环决策与执行。

Tool Use / Function Calling（工具调用 / 函数调用）

模型按约定结构选择工具并生成参数，由宿主程序执行后把结果返回模型。模型提出调用，不等于它亲自执行了外部操作。

MCP（Model Context Protocol，模型上下文协议）

用于连接 AI 应用与外部工具、数据源和服务的开放协议。它统一了能力发现、调用和上下文交换方式，但具体权限、安全与业务逻辑仍由客户端和服务端实现。

Harness（智能体运行框架）

Agent 中围绕模型运行的工程系统，包括 Prompt 组装、工具执行、上下文管理、权限、重试、状态保存和用户交互。可概括为：

Agent=Model+Harness+Tools / Environment\text{Agent}=\text{Model}+\text{Harness}+\text{Tools / Environment} Agent=Model+Harness+Tools / Environment

“Harness Engineering”关注如何把模型能力组织成稳定、可控、可恢复的工作流。

Skill（技能）

为 Agent 封装的可复用任务知识或工作流程，可能包含说明、脚本、模板和资源。Skill 告诉 Agent 某类任务应如何完成，Tool 则提供可实际调用的能力。

Memory（记忆）

Agent 用来保留跨步骤或跨会话信息的机制，可分为当前上下文中的短期记忆，以及存储在数据库、文件或检索系统中的长期记忆。

Planning（规划）

把目标拆解为步骤并根据执行结果调整路径。规划可以显式产生任务列表，也可以隐含在多轮工具调用中。

Observation（观察）

环境或工具执行后返回给 Agent 的信息，例如命令输出、网页内容、数据库结果和错误消息。

Context Engineering（上下文工程）

系统性地选择、组织和更新模型当前可见的信息，包括指令、历史、检索结果、工具说明、状态与记忆。它比单次 Prompt 优化覆盖的范围更广。

Guardrail（护栏）

限制模型或 Agent 行为的规则与控制机制，例如权限检查、输入输出过滤、工具白名单、审批和执行沙箱。

9. 多模态与语音

CLIP（Contrastive Language-Image Pre-training）

通过对比学习把图像和文本编码到共享表示空间，使匹配的图文向量更接近、不匹配的更远。它可用于零样本图像分类、图文检索和多模态表示，不是通用的图像生成器。

ASR（Automatic Speech Recognition，自动语音识别）

把语音转换为文本，也常称 Speech-to-Text（STT）。识别效果会受口音、噪声、专业词和多人重叠说话影响。

TTS（Text-to-Speech，文本转语音）

把文本转换为可播放语音。它与 ASR 的方向相反，语音助手播报、有声内容生成和无障碍朗读都是常见应用。

OCR（Optical Character Recognition，光学字符识别）

从图片或扫描文档中识别文字。文档理解系统通常还要处理版面、表格和阅读顺序，不只是字符识别。

VLM（Vision-Language Model，视觉语言模型）

联合处理图像与文本的模型，可完成看图问答、图片描述、视觉定位等任务。

10. 训练与优化基础

SGD（Stochastic Gradient Descent，随机梯度下降）

使用随机抽取的样本或小批量数据估计梯度并更新参数。严格说单样本是 stochastic，工程中常把 Mini-batch SGD 也简称 SGD。

Adam

根据梯度的一阶矩和二阶矩估计自适应调整每个参数的更新步长，是深度学习中常用的优化器。

Learning Rate（学习率）

控制每次参数更新的步长。过大会震荡或发散，过小则训练缓慢；实际训练常配合 Warmup 和衰减计划。

Batch / Batch Size（批次 / 批大小）

一次参数更新使用的样本集合及其数量。LLM 训练还会用 Token 数表示有效批大小。

Epoch（轮次）

训练数据被完整遍历一次。大规模预训练常更关心已处理 Token 数和训练 Step，而不是 Epoch。

Gradient Accumulation（梯度累积）

连续处理多个 Micro-batch，累积梯度后再更新一次参数，用较小显存模拟更大的有效批次。

Gradient Clipping（梯度裁剪）

限制梯度范数或数值范围，以降低梯度爆炸造成的训练不稳定。

Checkpoint（检查点）

训练过程中保存的模型参数及必要状态，可用于恢复训练、评估或部署。只保存权重未必能无缝恢复优化器进度。

11. 数字与单位补充

K / M / B / T

在模型参数、数据量和算力语境中，通常分别表示千、百万、十亿和万亿。例如 7B 参数约为 70 亿参数。

“兆”的歧义

中文日常技术材料里，“1 兆”可能指一百万，也可能在传统大数或地区用法中指万亿；存储语境里“兆”又常对应 MB。为避免误读，模型参数和金额最好直接写 million / billion / trillion 或“百万 / 十亿 / 万亿”，不要只写“兆”。

FLOPs / FLOPS

技术材料中常用 FLOPs 表示一次计算所需的浮点运算次数，用 FLOPS 表示每秒浮点运算能力。更严格的单位写法是用 FLOP 表示一次浮点运算，用 FLOP/s 表示每秒运算数。实际文章经常混用大小写，因此讨论算力时应说明指的是计算工作量还是吞吐能力。
