程序员常用术语

发表于2026-08-08|更新于2026-08-09|代码编程基础概念

1. 接口与数据

API（Application Programming Interface，应用程序编程接口）

一套供其他程序调用的规则。API 约定“可以调用什么、传入什么、返回什么”，具体实现可以隐藏在接口后面。Web API 常通过 HTTP 提供，但 API 并不等于 HTTP 接口，操作系统函数、语言库方法也属于 API。

SDK（Software Development Kit，软件开发工具包）

围绕某个平台或服务提供的一组开发工具，通常包含客户端库、示例、文档和调试工具。API 是能力契约，SDK 是帮助开发者使用这套契约的工具包。

CLI（Command-Line Interface，命令行界面）

通过终端输入命令来操作程序的用户界面，例如执行 git status 查看仓库状态。这里的 Interface 指人与程序交互的“界面”，不是 API 语境中的“接口”。CLI 适合自动化、远程操作和批处理，也方便把多条命令组合成脚本。

GUI（Graphical User Interface，图形用户界面）

通过窗口、图标、菜单和按钮等图形元素与程序交互的界面。例如，在文件管理器中拖动文件、在浏览器中点击按钮，都属于 GUI 操作。GUI 更直观，CLI 则更适合精确操作和自动化；同一个软件也可以同时提供两种界面。

IDE（Integrated Development Environment，集成开发环境）

把编写、运行和调试代码所需的工具集成在一个应用中。IDE 通常包含代码编辑器、语法检查、代码补全、调试器、构建工具和版本管理入口，例如 IntelliJ IDEA、PyCharm 和 Visual Studio。VS Code 更常被归为代码编辑器，但安装扩展后也能提供接近 IDE 的开发体验。

JSON（JavaScript Object Notation）

英文全称 JavaScript Object Notation 是正确的，中文通常译为“JavaScript 对象表示法”。JSON 的语法受到 JavaScript 对象字面量的影响，但它是一种独立于编程语言的文本数据格式，并不限定在 JavaScript 中使用。Python、Java、Go、C# 等语言都有读写 JSON 的库。

Schema（模式）

对数据结构的约束，例如字段名、类型、是否必填以及取值范围。数据库表结构、JSON Schema 和接口请求参数定义都可称为 Schema。

Serialization / Deserialization（序列化 / 反序列化）

序列化是把内存中的对象转成便于存储或传输的格式；反序列化是把数据还原成程序对象。JSON、Protocol Buffers 都可作为序列化格式。

NaN（Not a Number）

浮点数系统中表示“不是有效数值结果”的特殊值，例如某些环境中的 0/0。Pandas、NumPy 等数据工具也常用 NaN 表示缺失值，但“NaN 就是缺失值”并不严谨。不同语言对除零的处理也不同：可能得到 NaN、无穷大或直接抛出异常。

NULL / null / None

这几个写法都与“没有值”有关，但所属语言和具体语义不同：

写法 常见语言或环境 含义与用法
NULL SQL；C、C++ 的旧式指针代码 SQL 中表示未知或缺失的数据，通常写成大写关键字；C、C++ 中的 NULL 是传统的空指针常量，现代 C++ 更推荐 nullptr
None Python；Rust 的 Option::None Python 中是一个单例对象，函数没有显式返回值时会返回 None；Rust 的 None 是 Option 枚举中表示“没有值”的分支
null JavaScript、Java、C#、Kotlin、PHP、Dart 等 通常表示引用没有指向对象，或变量被明确设置为空；各语言对可空类型和空值检查的规则不同

在 SQL 中，NULL 表示“值未知”，因此 NULL = NULL 不会得到普通意义上的 true，判断时应使用 IS NULL。JavaScript 中还存在 undefined：null 通常表示开发者主动设置“这里没有值”，undefined 更常表示变量或属性尚未赋值。其他语言也可能采用不同名称，例如 Go 和 Swift 使用 nil。

2. 编码与代码组织

Vibe Coding

开发者主要用自然语言描述意图，让 AI 生成、修改和运行代码，再根据结果继续迭代的编程方式。它降低了写样板代码的成本，但不意味着可以跳过需求澄清、代码审查、测试和安全检查。

KISS（Keep It Simple, Stupid）

优先选择足够简单、能够解决当前问题的设计。它反对不必要的复杂度，不反对为了正确性而存在的复杂逻辑。

Code Review / CR（代码评审）

代码合并前由其他开发者检查正确性、可读性、安全性和设计合理性的过程。评审应关注问题本身，不宜只做格式检查。

PR / MR（Pull Request / Merge Request）

请求把一个分支的改动合并到另一个分支。GitHub 常称 PR，GitLab 常称 MR，核心都是承载变更说明、讨论、评审和自动检查。

3. 测试与质量保障

TC（Test Case，测试用例）

描述测试前置条件、输入、执行步骤和预期结果的一条检查路径。口语中的“TC 评审”通常指 Test Case Review，即测试用例评审。

Unit Test（单元测试）

验证函数、类或模块等小范围单元的行为，追求运行快、定位准。单元测试通常会隔离数据库、网络等外部依赖。

E2E Test（End-to-End Test，端到端测试）

从用户入口到后端依赖走完整业务链路。它更贴近真实使用，但运行慢、定位问题也比单元测试困难。

Smoke Test（冒烟测试）

在发布或大规模测试前，先验证最核心路径能否跑通。冒烟测试失败通常意味着版本暂不值得继续做更细的验证。

4. 版本管理与交付

Repository / Repo（代码仓库）

保存项目文件及其版本历史的地方。Git 仓库可以在本地存在，也可以同步到 GitHub、GitLab 等远端平台。

Branch（分支）

从某个提交点分出的独立开发线，用于隔离功能开发、修复和发布工作。

Commit（提交）

对一组文件变更的版本快照。好的提交通常范围清晰，说明“为什么改”而不只描述“改了什么”。

Merge / Rebase

Merge 通过合并提交整合两条历史；Rebase 把一组提交重新放到新的基点上，使历史更线性。已经被多人共享的提交通常不宜随意 Rebase 后强推。

Rollout（发布放量）

在软件交付语境中，指把新版本逐步部署并扩大覆盖范围。它和 LLM 强化学习中的 rollout 不是同一个概念。

Rollback（回滚）

版本出现严重问题时恢复到上一个稳定状态。能否快速回滚取决于代码、配置和数据变更是否向后兼容。

5. 性能与复杂度

Big O Notation（大 O 表示法）

描述输入规模增大时，算法时间或空间消耗的渐近上界。常见的 O(1)、O(log n)、O(n)、O(n log n) 和 O(n²) 分别表示常数阶、对数阶、线性阶、线性对数阶和平方阶。工程讨论中常用 Big O 概括主要增长量级，但它不直接等于真实运行时间。

Time Complexity / Space Complexity（时间 / 空间复杂度）

时间复杂度描述计算步骤随输入规模的增长，空间复杂度描述额外内存的增长。工程上还需考虑常数项、缓存命中、I/O 和并行度。

RT（Response Time，响应时间）

在服务性能监控中，RT 通常是 Response Time 的缩写，表示一次请求从开始到响应完成的总耗时。它可能包含排队、网络传输、服务计算和下游调用等时间。例如，客户端在 10:00:00.000 发出请求，在 10:00:00.120 收到完整响应，这次请求的 RT 就是 120 ms。

RT 的统计起点和终点取决于监控位置。客户端统计的 RT 通常包含往返网络耗时，服务端统计的 RT 往往只覆盖请求进入服务到响应离开服务的时间。因此，比较两个系统的 RT 前要先确认测量口径。在其他语境中，RT 也可能表示 Real-Time（实时），不能只看缩写判断。

Latency（延迟）

Latency 是更宽泛的“等待或传递延迟”，可以描述网络单向延迟、一次远程调用的耗时、数据库查询延迟，也可以表示从请求发出到收到首字节的时间。性能指标常看 P50、P95、P99 等分位数，因为平均值可能掩盖少量特别慢的请求。

RT 和 Latency 的主要区别如下：

术语 通常关注什么 示例
RT 一次请求从开始到响应完成的端到端总耗时 接口完整返回耗时 120 ms
Latency 更广义的等待时间，可以只描述链路或某个处理阶段 网络延迟 20 ms、首字节延迟 80 ms

实际工作中，许多监控平台会直接用 Latency 表示接口 RT，两者并没有绝对统一的边界。阅读指标时应以平台对起点、终点和统计范围的定义为准。

Throughput（吞吐量）

单位时间内处理的工作量，可以用请求数、任务数、数据量或 Token 数表示。例如 QPS、每秒处理的消息数和 MB/s 都属于吞吐量指标。高吞吐不一定意味着低延迟。

QPS（Queries Per Second，每秒查询数）

表示系统每秒处理的查询或请求数量，是衡量吞吐量的常用指标。虽然英文使用 Queries，QPS 在 Web 服务中并不只指数据库查询，也常表示接口每秒收到或完成的请求数。

QPS=统计周期内的请求数统计周期秒数\text{QPS}=\frac{\text{统计周期内的请求数}}{\text{统计周期秒数}} QPS=统计周期秒数统计周期内的请求数​

例如，某接口 60 秒内处理了 6000 个请求，平均 QPS 为 100。平均 QPS 可能掩盖短时流量尖峰，容量规划通常还需要观察峰值 QPS，并注明统计的是全部请求、成功请求还是实际完成的请求。

QPS 和 RT 分别回答“系统每秒处理多少请求”和“一个请求要等多久”。系统接近容量上限时，即使 QPS 暂时没有继续上升，排队也可能让 RT 快速增大。

Cache（缓存）

把高频访问结果保存在更快的介质中，以减少重复计算或慢速读取。缓存需要考虑过期、淘汰、一致性、穿透和雪崩等问题。

6. 服务与分布式系统

Client / Server（客户端 / 服务端）

客户端发起请求，服务端提供数据或能力。一个程序在不同交互中可能同时扮演客户端和服务端。

REST（Representational State Transfer，表述性状态转移）

一种面向资源的 Web 接口设计风格，通常使用 HTTP 方法表达操作。使用 HTTP 和 JSON 的接口不一定天然符合 REST。

Timeout / Retry（超时 / 重试）

超时限制等待时间，重试用于处理临时失败。无上限或无退避的重试会放大故障，常配合指数退避、抖动和最大次数。

7. 故障、安全与协作

Bug / Defect（缺陷）

程序行为与需求或合理预期不一致。线上出现的异常现象是 symptom（症状），真正导致它的原因才是 root cause（根因）。

Hotfix（紧急修复）

针对生产环境高优问题快速发布的修复。速度重要，但仍应保留最基本的评审、验证和回滚方案。

RCA（Root Cause Analysis，根因分析）

从故障现象追到机制原因，并形成可验证的改进措施。RCA 的目的不是寻找背锅者，而是减少同类问题再次发生。

SLA / SLO / SLI

SLI（Service Level Indicator，服务等级指标）是实际测量值，例如请求成功率；SLO（Service Level Objective，服务等级目标）是团队为 SLI 设定的目标；SLA（Service Level Agreement，服务等级协议）是与客户约定的服务承诺，未达到时可能触发赔偿。三者不应混用。

Authentication / Authorization（认证 / 授权）

Authentication 回答“你是谁”，Authorization 回答“你能做什么”。登录成功不代表拥有所有资源权限。

Token（访问令牌）

在鉴权语境中，Token 是代表身份或权限的凭证。它和自然语言处理中的文本 Token 只是同名概念，泄露访问令牌可能等同于泄露密码。

P0 / P1 / P2

常用于表示故障或任务优先级，数字越小通常越紧急。但每家公司定义不同，使用时应以团队规则为准。

8. 一组容易混淆的词

术语 关注点 不要混成
API / SDK 能力契约 / 使用工具包 两者并非同义词
NULL / NaN 没有值 / 非有效数值结果 NaN 不天然等于缺失值
RT / Latency 完整请求响应时间 / 更广义的链路或阶段延迟 两者在部分监控平台中会采用相同口径
QPS / RT 每秒请求数量 / 单个请求耗时 一个衡量吞吐量，一个衡量等待时间
Authentication / Authorization 身份 / 权限 认证通过不等于有权限
Rollout / Rollback 发布放量 / 恢复旧版本 方向相反
