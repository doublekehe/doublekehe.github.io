MiniOneRec 框架详解

MiniOneRec 是 OneRec 核心流程的轻量开源实现。它保留了 OneRec 将推荐建模为序列生成的主要思路，并使用公开的 Amazon Review 数据、Qwen 系列模型以及完整的 SID、SFT 和 RL 代码，将工业级方案压缩到可以复现和分析的规模。[^1][^2]

与常见的“召回-排序-重排”多阶段级联结构不同，MiniOneRec 让 LLM 根据用户行为历史直接生成下一件商品。整个过程可以概括为：

表 1　MiniOneRec 从商品离散化到在线推理的完整流程
阶段 主要操作 得到什么
商品离散化 编码商品标题和描述，再用 RQ-VAE 量化 每件商品得到一个SID码本，比如[a_5, b_12, c_44]
监督微调 用历史 SID 预测下一 SID，同时加入文本与 SID 的对齐任务 LLM 学会理解和生成 SID
推荐强化学习 通过 constrained beam search 产生候选，用 ACC 与 rank reward 计算反馈 正确商品概率提高，靠前的错误商品受到更强惩罚
在线推理 生成合法 SID，再查询离线映射表 SID 被还原成业务商品 ID

如果直接以商品 ID 注册成 token，一百万件商品就需要向词表加入一百万个彼此独立的 token，词表和输出层会随着商品规模同步增长。Semantic ID 使用少量基础 token 的组合表示商品，比如每个商品用 3层码本，每层 256 个码 来表示，只需加入 3×256=7683\times256=7683×256=768 个 SID token，就可以组成 2563256^32563 个不同的 SID表示的商品。这样既能覆盖大规模商品库，也能通过共享前缀保留商品之间的部分语义关系。MiniOneRec 先用 RQ-VAE 为每件商品生成 SID，再围绕 SID 完成监督微调和强化学习。

这条链路需要解决三个问题：商品如何变成 SID，LLM 如何理解这些新增 token，以及生成的 SID 如何对应回商品。论文中的 SID 构建、Full-Process SID Alignment 和带约束解码的 GRPO，分别承担这三部分工作。

2.1 将商品文本编码为语义向量

对商品 iii，MiniOneRec 先拼接标题和描述：

ti=concat⁡(titlei,descriptioni)t_i = \operatorname{concat}(\text{title}_i,\text{description}_i) ti​=concat(titlei​,descriptioni​)

论文使用 Qwen3-Embedding-4B 生成商品向量，并在训练 RQ-VAE 时冻结文本编码器。这样可以保持语义空间稳定：标题和描述相近的商品通常具有相近的向量，也更容易在后续量化中共享部分 SID。开源代码先将这些向量保存为 .npy，再由 rq/rqvae.py 训练量化器。[^2]

2.2 RQ-VAE：逐层量化残差

普通向量量化只从一个码本中选择一次最近向量。RQ-VAE（Residual Quantized VAE）则逐层量化残差，让多个离散码共同表示一件商品。

LLM 的 tokenizer 不会把完整 SID 注册成一个独立 token，而是分别加入三组层级 token。三层一共只需新增 3×256=7683\times256=7683×256=768 个 token，组合空间却可以达到 2563=224256^3=2^{24}2563=224。

第一层量化原始语义向量，后两层继续编码尚未被表示的残差。因此，语义相近的商品往往会共享较长的 SID 前缀。这些前缀来自向量量化，与人工定义的类目层级不同，每个残差码也没有固定的业务含义。

2.3 SID 如何重新对应到商品 ID

SID 只是模型使用的离散表示，业务系统仍然通过原始商品 ID 识别商品。数据转换阶段会保存两个方向的映射：

训练时，第一张表负责把用户历史中的 item_id 转成 history_item_sid 和 item_sid；推理时，第二张表再把模型生成的完整 SID 还原成标题和 item_id。SID 与商品之间的对应关系由离线映射表确定，不依赖 LLM 记忆商品 ID。

不同商品可能量化到同一个 SID，这种情况称为 collision。rq/generate_indices.py 会检测冲突，并使用带 Sinkhorn 约束的量化方式重新分配，最多重试 20 轮；仓库还提供 constrained RQ-Kmeans、RQ-Kmeans+ 等构建方法。由于发生碰撞的 SID 无法唯一还原商品，生成索引后需要检查脚本输出的 collision rate。

这里的 ttt 是目标商品 SID 内部的 token 位置，不是用户历史中的商品位置。模型依次学会生成 <a_12>、<b_7>、<c_44>。

3.2 Full-Process SID Alignment

RQ-VAE 生成的 SID 保留了商品向量之间的相似关系，但这些信息仍停留在量化空间中。将 <a_12>、<b_7> 等字符串加入 LLM tokenizer，只是让模型能够读写这些 token；新增的 token embedding 还没有和商品文本建立联系。

sft.py 先收集全部 SID token，通过 tokenizer.add_tokens() 扩充词表，再使用 resize_token_embeddings() 扩展模型的输入、输出矩阵。此时，模型虽然可以生成 <a_12><b_7><c_44>，却还不知道它对应鼠标，也无法将它与“办公外设”“人体工学”等概念联系起来。

仅使用“历史 SID 预测下一 SID”任务，模型可以学习商品之间的共现关系，却很难将预训练阶段获得的文本知识迁移到 SID。Full-Process SID Alignment 通过文本、SID 和用户历史之间的多种转换任务，为两个空间建立直接联系。在实现上，它是一套贯穿 SFT 和 RL 的多任务训练方法。

3.3 Recommendation Tasks 与 Alignment Tasks

论文将训练样本分为 Recommendation Tasks 和 Alignment Tasks。前者学习用户下一步可能交互的商品，后者补充 SID 对应的商品语义。

3.4 对齐任务如何训练

这些任务都会转换成 instruction-response 样本。无论目标是商品标题还是 SID，模型都使用同一个自回归 next-token prediction 目标。设 mmm 表示任务类型，对齐损失可以写成：

Lalign=∑mλm E(x,y)∼Dm[−∑t=1∣y∣log⁡πθ(yt∣x,y<t)]\mathcal{L}_{\text{align}} =\sum_m \lambda_m\, \mathbb{E}_{(x,y)\sim\mathcal{D}_m} \left[-\sum_{t=1}^{|y|} \log \pi_\theta(y_t\mid x,y_{<t})\right] Lalign​=m∑​λm​E(x,y)∼Dm​​​−t=1∑∣y∣​logπθ​(yt​∣x,y<t​)​

Dm\mathcal{D}_mDm​ 是第 mmm 类任务的数据集，λm\lambda_mλm​ 表示它在混合数据中的相对占比。当前代码通过 ConcatDataset 直接拼接各类样本，没有额外的对比学习头或映射网络，因此各任务的样本量决定了它们对总损失的实际贡献。

SFT 阶段的总目标可以理解为：

LSFT=Lrec+Lalign\mathcal{L}_{\text{SFT}} =\mathcal{L}_{\text{rec}}+\mathcal{L}_{\text{align}} LSFT​=Lrec​+Lalign​

训练时，梯度会同时更新 SID embedding 和 LLM 参数，使新增 token 逐步进入模型原有的语义空间。sft.py 也提供了 freeze_LLM=True，用于冻结 LLM、只训练 SID embedding；但当前 main 分支在这条分支中使用了尚未赋值的 original_vocab_size，需要补充扩词表前的词表大小后才能使用。

3.5 RL 阶段继续保持 SID 对齐

SFT 建立了 SID 与文本之间的联系，随后的 RL 还会继续改变模型的生成分布。为了在优化推荐结果时保留这种联系，MiniOneRec 在 RL 数据中继续加入可以准确计算 reward 的跨空间任务。

4.1 Constrained decoding

真实代码使用 tokenizer 的整数 token ID 建立这张前缀表。第一次查询时，key 中还包含 ### Response:\n 对应的模板前缀；生成第一枚 SID token 后，再根据已经生成的 SID 前缀查询后继 token。

每生成一步，ConstrainedLogitsProcessor 都会查询当前前缀，把其余 token 的 logit 设为 −∞-\infty−∞：

ppp 是当前 SID 前缀，A(p)\mathcal{A}(p)A(p) 是合法的下一 token 集合。比如已经生成 <a_12> 后，<b_4> 会在 softmax 前被屏蔽，模型没有机会沿着这条非法路径继续生成。

Constrained decoding 直接在合法 SID 组成的前缀树上搜索。每一步只扩展仍然可以到达真实商品的节点；如果当前前缀没有合法后继，代码会直接生成 EOS。这样可以在生成过程中阻断无效路径，避免把计算浪费在无法对应商品的 SID 上。

当前 minionerec_trainer.py 实际使用 SID 构建前缀表，与默认启用的“输出 SID”类 RL 任务一致。若启用“SID 到标题”类任务，还需要把标题加入约束集合。运行时可以通过 CC 指标检查约束是否生效：CC 为 0 表示没有生成无效商品；如果 CC 非 0，需要继续检查 logits processor 和 Transformers 版本。

4.2 Constrained beam search 生成多个候选

对同一个 prompt 进行多次普通采样，可能反复得到同一热门商品。MiniOneRec 使用宽度为 GGG 的 constrained beam search，在合法路径中保留多个高分候选。论文实验取 G=16G=16G=16，并将长度惩罚设为 0，因为所有 SID 的长度基本相同。

当前 minionerec_trainer.py 在设置 num_beams=G 的同时开启 do_sample=True，并加入 temperature warper，因此代码实现属于带采样的 beam search，在保留高分路径的同时引入了一定随机性。rl.sh 通过 beam_search=True 启用这条分支。

最终，一个 prompt 会得到 GGG 条不同的完整 SID，每条 SID 对应一件候选商品，也就是图1中的 G different items。

5. 用强化学习优化候选排序

Constrained decoding 保证生成结果属于商品库，强化学习则进一步调整这些合法商品的概率和顺序。MiniOneRec 使用 ACC reward 判断候选是否命中真实商品，再用 rank reward 区分不同位置上的错误候选。两种 reward 都作用于完整 SID，不计算候选与 label 之间的前缀重合度。

5.1 Reward 的计算粒度

对一个 prompt xxx，模型产生 GGG 个完整候选：

Y(x)={y(1),y(2),…,y(G)}Y(x)=\{y^{(1)},y^{(2)},\ldots,y^{(G)}\} Y(x)={y(1),y(2),…,y(G)}

每个 y(k)y^{(k)}y(k) 是一件商品的完整 SID，先得到一个标量分数 SkS_kSk​。GRPO 再在同一组内计算均值和标准差：

A^k=Sk−μ1:Gσ1:G+ϵ\hat A_k=\frac{S_k-\mu_{1:G}}{\sigma_{1:G}+\epsilon} A^k​=σ1:G​+ϵSk​−μ1:G​​

每个完整 SID 都有自己的 reward，但 advantage 需要在同一组候选中归一化。随后，这个序列级 advantage 会用于该候选所有生成 token 的策略梯度。具体来说：

  • 每个完整候选 SID 对应一个序列级 reward；
  • rank reward 的值依赖该候选在整组中的位置；
  • 得到序列级 advantage 后，它会参与该候选每个生成 token 的策略梯度计算。

Reward 在序列级计算，策略损失则在 token 级展开。

5.2 ACC reward：只判断完整商品是否命中

设真实下一商品为 ete_tet​，第 kkk 个候选为 eke_kek​：

RACC(ek,et)={1,ek=et0,ek≠etR_{\text{ACC}}(e_k,e_t)= \begin{cases} 1,&e_k=e_t\\ 0,&e_k\neq e_t \end{cases} RACC​(ek​,et​)={1,0,​ek​=et​ek​=et​​

代码会去掉生成文本和目标 SID 中的引号、换行，再进行字符串精确比较。只有完整 SID 相同才得到 1，共享部分前缀仍然记为 0。

5.3 Rank reward：惩罚靠前的错误商品

只有 ACC 时，所有错误商品都是 0。排第 1 的错误商品和排第 16 的错误商品没有区别，但前者显然更需要被压低。

当前代码没有把每条序列的 score 单独传给 reward 函数，而是直接用 completion 在每组中的返回位置 i % num_generations 作为 ρk\rho_kρk​。因此这段实现依赖生成器按 beam score 返回候选；一旦替换生成后端或自行重排 completions，也必须保持这个顺序约定。

5.4 ACC 与 rank reward 如何配合

图1中，命中商品的 rank reward 为 0，因为两个 reward 的作用不同：

  • ACC 负责“拉高正确商品”，给命中项 +1+1+1；
  • Rank 负责“区分错误商品有多糟”，只给负样本惩罚。

命中项的总 reward 是 1+0=11+0=11+0=1。Rank reward 只负责区分负样本的位置，不再重复增加命中奖励。

论文对当前组中的实际负样本进行归一化。rl.py 的 ndcg_rule_reward 则先为 GGG 个位置计算固定权重：

如果整组 beam 都没有真实商品，ndcg_rule_reward 会把这组 rank reward 全部设为 0。此时 ACC 也全部为 0，组内 advantage 随之变为 0，这条 prompt 只剩 KL 项约束当前策略接近参考模型。只有 label 已经进入候选组时，rank reward 才会产生相对排序信号。

这些 advantage 对应如下更新方向：

  • 提高 <a_12><b_7><c_44> 整条生成轨迹的概率；
  • 明显压低排第 1 的错误轨迹 <a_12><b_7><c_91>；
  • 对排名更靠后的两个错误候选做较弱的负向更新。

论文中的 GRPO 在每个 SID token 位置计算新旧策略的概率比，使用 clipping 控制更新幅度，并通过 KL 项限制策略偏离参考模型。序列级 advantage 会用于该候选的每个生成位置，最终更新仍然落实到自回归生成的每一步。

8. 总结

MiniOneRec 使用 RQ-VAE 将商品编码成三层 SID，再让 LLM 根据用户的 SID 历史生成下一件商品。Full-Process SID Alignment 连接 SID 与商品文本，constrained beam search 将生成限制在真实商品目录中，ACC 和 rank reward 分别提供命中信号与负样本排序信号，GRPO 再将组内 reward 转换成模型更新。

整套方法的分工比较清楚：RQ-VAE 负责商品离散化，Alignment 负责 SID 语义，constrained decoding 负责生成合法性，ACC 与 rank reward 负责推荐质量，离线映射表负责将最终 SID 还原成业务商品 ID。
