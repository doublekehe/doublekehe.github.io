MiniOneRec 框架详解

MiniOneRec 是 OneRec 核心流程的轻量开源实现。它保留了 OneRec 将推荐建模为序列生成的主要思路，并使用公开的 Amazon Review 数据和 Qwen 模型复现 SID 构建、SFT 与 RL 的完整训练流程，使这套框架更容易分析和复现。[1][2]

与常见的“召回—排序—重排”多阶段级联结构不同，MiniOneRec 让 LLM 根据用户行为历史直接生成推荐商品列表。MiniOneRec 的完整流程包括几个核心环节：

表 1　MiniOneRec 核心三大环节
阶段 主要操作 得到什么
商品离散化 用 Embedding 模型编码商品标题和描述，再用 RQ-VAE 量化 每件商品得到一个多层 SID，比如 <a_5><b_12><c_44>
监督微调 用历史 SID 预测下一 SID，同时加入文本与 SID 的对齐任务 LLM 学会理解和生成 SID
强化学习 在合法 SID 空间中生成一组候选，用 ACC 与 rank reward 计算反馈 正确商品概率提高，靠前的错误商品受到更强惩罚

2.1 将商品文本编码为语义向量

对商品 iii，MiniOneRec 先拼接标题和描述：

论文使用 Qwen3-Embedding-4B 生成商品向量，并在训练 RQ-VAE 时冻结文本编码器。这样可以保持语义空间稳定：标题和描述相近的商品通常具有相近的向量，也更容易在后续量化中共享部分 SID。[1]

2.3 SID 如何重新对应到商品 ID

SID 是模型使用的离散表示，业务系统仍然通过原始商品 ID 识别商品。因此，离线构建 SID 时需要同时保存双向映射：

训练数据通过第一条映射把用户历史中的商品 ID 转换成 SID，模型生成结果再通过第二条映射还原成业务商品 ID。

不同商品有可能量化到同一个 SID，这种情况称为 SID collision。离线构建阶段需要检测并消除冲突，使最终保留的每个完整 SID 都能唯一对应一件商品。否则，即使模型生成了合法 SID，也无法确定应该返回哪一个商品。

3.2 Full-Process SID Alignment

RQ-VAE 生成的 SID 保留了商品向量之间的相似关系，但这些信息仍停留在量化空间中。将 <a_12>、<b_7> 等字符串加入 LLM 的分词词表，只是让模型能够读写这些 token；新增的 token 向量表示还没有和商品文本建立联系。

将三组 SID token 加入 LLM 词表后，模型的输入 Embedding 和输出层会增加相应位置。此时，模型虽然可以读写 <a_12><b_7><c_44>，却还不知道它对应鼠标，也无法将它与“办公外设”“人体工学”等概念联系起来。

最基础的生成式推荐任务只有一个方向：输入用户的 SID 历史，预测下一件商品的 SID。模型可以由此学习商品之间的共现关系，却很难将预训练阶段获得的文本知识迁移到 SID。

Full-Process SID Alignment 在这个主任务之外，增加了文本、SID 和用户历史之间的转换任务。假设“人体工学无线鼠标”的 SID 是 <a_12><b_7><c_44>，可以构造下面这些训练样本：

标题或描述与 SID 的双向转换，让模型理解单件商品；文本历史与 SID 历史之间的转换，则把用户行为和商品语义连接起来。这些样本会与主推荐任务一起参与训练，不需要额外增加一个 Alignment 网络。

3.3 Recommendation Tasks 与 Alignment Tasks

论文将训练样本分为 Recommendation Tasks 和 Alignment Tasks。前者学习用户下一步可能交互的商品，后者补充 SID 对应的商品语义。

3.4 对齐任务如何训练

这些任务都会转换成 instruction-response 样本。无论目标是商品标题还是 SID，模型都使用同一个自回归 next-token prediction 目标。将推荐任务与对齐任务组成的混合数据集记为 DSFT\mathcal{D}_{\text{SFT}}DSFT​，训练损失可以统一写成：

LSFT=E(q,y)∼DSFT[−∑t=1∣y∣log⁡πθ(yt∣q,y<t)]\mathcal{L}_{\text{SFT}} =\mathbb{E}_{(q,y)\sim\mathcal{D}_{\text{SFT}}} \left[-\sum_{t=1}^{|y|} \log \pi_\theta(y_t\mid q,y_{<t})\right] LSFT​=E(q,y)∼DSFT​​​−t=1∑∣y∣​logπθ​(yt​∣q,y<t​)​

不同任务共享同一个自回归训练目标，不需要额外增加对比学习头或独立的映射网络。训练过程中，SID token 的 Embedding 和 LLM 参数一起更新，文本任务提供的梯度会逐步把新增 SID token 拉入模型原有的语义空间。各类任务在训练数据中的占比，则决定了它们对总损失的实际影响。

3.5 RL 阶段继续保持 SID 对齐

SFT 建立了 SID 与文本之间的联系，随后的 RL 还会继续改变模型的生成分布。为了避免模型在追求推荐 reward 时丢失这些语义关系，MiniOneRec 在 RL 阶段继续保留能够准确校验答案的推荐任务和对齐任务。

4. 如何生成合法的 SID

4.1 Constrained decoding

系统会把每个合法前缀对应的“下一步允许 token”写入哈希表：

每生成一步，系统都会根据当前前缀查询允许的后继 token，并把其他 token 的 logit 设为 −∞-\infty−∞：

ℓv′={ℓv,v∈A(p)−∞,v∉A(p)\ell'_v= \begin{cases} \ell_v,&v\in\mathcal{A}(p)\\ -\infty,&v\notin\mathcal{A}(p) \end{cases} ℓv′​={ℓv​,−∞,​v∈A(p)v∈/A(p)​

ppp 是当前 SID 前缀，A(p)\mathcal{A}(p)A(p) 是合法的下一 token 集合。比如已经生成 <a_12> 后，<b_4> 会在 softmax 前被屏蔽，模型没有机会沿着这条非法路径继续生成。

Constrained decoding 相当于在合法 SID 组成的前缀树上搜索。每一步只扩展仍然可以到达真实商品的节点；完整 SID 生成后结束当前路径。这样可以在生成过程中阻断无效组合，最终得到的每条 SID 都能映射到商品目录中的真实商品。

4.2 Constrained beam search 生成多个候选

对同一个 prompt 进行多次普通采样，可能反复得到同一热门商品。MiniOneRec 使用宽度为 GGG 的 constrained beam search，在合法路径中保留多个高分候选。论文实验取 G=16G=16G=16，并将长度惩罚设为 0，因为所有 SID 的长度基本相同。

与对同一 prompt 反复独立采样相比，beam search 会同时维护多条高概率路径，更容易得到互不相同的候选。再叠加合法前缀约束后，一个 prompt 最终得到 GGG 条不同且有效的完整 SID，每条 SID 对应一件候选商品，也就是图 1 中的 G different items。

5. 用强化学习优化候选排序

Constrained decoding 保证生成结果属于商品库，强化学习则进一步调整这些合法商品的概率和顺序。MiniOneRec 使用 ACC reward 判断候选是否命中真实商品，再用 rank reward 区分不同位置上的错误候选。两种 reward 都作用于完整 SID，不计算候选与 label 之间的前缀重合度。

5.1 Reward 的计算粒度

对一个 prompt qqq，模型产生 GGG 个完整候选：

Y(q)={y(1),y(2),…,y(G)}Y(q)=\{y^{(1)},y^{(2)},\ldots,y^{(G)}\} Y(q)={y(1),y(2),…,y(G)}

每个 y(k)y^{(k)}y(k) 是一件商品的完整 SID，先得到一个标量分数 SkS_kSk​。GRPO 再在同一组内计算均值和标准差：

A^k=Sk−μ1:Gσ1:G+ϵ\hat A_k=\frac{S_k-\mu_{1:G}}{\sigma_{1:G}+\epsilon} A^k​=σ1:G​+ϵSk​−μ1:G​​

每个完整 SID 都有自己的 reward，但 advantage 需要在同一组候选中归一化。随后，这个序列级 advantage 会用于该候选所有生成 token 的策略梯度。具体来说：

  • 每个完整候选 SID 对应一个序列级 reward；
  • rank reward 的值依赖该候选在整组中的位置；
  • 得到序列级 advantage 后，它会参与该候选每个生成 token 的策略梯度计算。

Reward 在序列级计算，策略损失则在 token 级展开。

5.2 ACC reward：只判断完整商品是否命中

设真实下一商品为 ete_tet​，第 kkk 个候选为 eke_kek​：

RACC(ek,et)={1,ek=et0,ek≠etR_{\text{ACC}}(e_k,e_t)= \begin{cases} 1,&e_k=e_t\\ 0,&e_k\neq e_t \end{cases} RACC​(ek​,et​)={1,0,​ek​=et​ek​=et​​

只有完整 SID 与真实商品一致时才得到 1，共享部分 SID 前缀仍然记为 0。ACC 判断的是“是否命中同一件商品”，而不是两个 SID 在语义上有多相似。

5.3 Rank reward：惩罚靠前的错误商品

只有 ACC 时，所有错误商品都是 0。排第 1 的错误商品和排第 16 的错误商品没有区别，但前者显然更需要被压低。

5.4 ACC 与 rank reward 如何配合

图 1 中，命中商品的 rank reward 为 0，因为两个 reward 的作用不同：

  • ACC 负责“拉高正确商品”，给命中项 +1+1+1；
  • Rank 负责“区分错误商品有多糟”，只给负样本惩罚。

命中项的总 reward 是 1+0=11+0=11+0=1。Rank reward 只负责区分负样本的位置，不再重复增加命中奖励。两种信号结合后，模型既要把正确商品推到前面，也要优先压低当前最容易混淆的高排名错误商品。

这些 advantage 对应如下更新方向：

  • 提高 <a_12><b_7><c_44> 整条生成轨迹的概率；
  • 明显压低排第 1 的错误轨迹 <a_12><b_7><c_91>；
  • 对排名更靠后的两个错误候选做较弱的负向更新。

GRPO 会把同一候选的序列级 advantage 用到该 SID 的每个生成位置。正 advantage 提高整条生成轨迹的概率，负 advantage 则降低对应轨迹的概率。训练时还会比较新旧策略在每个 token 上的概率，使用 clipping 限制单次更新幅度，并通过 KL 项防止当前策略偏离参考模型过远。

7. 总结

MiniOneRec 使用 RQ-VAE 将商品编码成三层 SID，再让 LLM 根据用户的 SID 历史生成下一件商品。Full-Process SID Alignment 连接 SID 与商品文本，constrained beam search 将生成限制在真实商品目录中，ACC 和 rank reward 分别提供命中信号与负样本排序信号，GRPO 再将组内 reward 转换成模型更新。

整套方法的分工比较清楚：RQ-VAE 负责商品离散化，Alignment 负责 SID 语义，constrained decoding 负责生成合法性，ACC 与 rank reward 负责推荐质量，离线映射表负责将最终 SID 还原成业务商品 ID。
