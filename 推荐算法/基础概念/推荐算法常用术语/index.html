推荐算法常用术语

发表于2026-08-08|更新于2026-08-09|推荐算法基础概念

1. 基础问题与经典方法

RS（Recommender System，推荐系统）

根据用户、物品和上下文信息，从候选集中挑选并排序用户可能感兴趣的内容。完整系统通常包含召回、粗排、精排和重排，不是一个模型就能概括。

CF（Collaborative Filtering，协同过滤）

利用用户与物品之间的行为数据，通过相似关系做推荐。经典做法包括 UserCF 和 ItemCF；它依赖群体行为，不要求先理解物品内容。

UserCF（基于用户的协同过滤）

寻找与目标用户兴趣相似的用户，再推荐相似用户喜欢而目标用户尚未接触的物品。用户规模大、兴趣变化快时，相似度维护成本较高。

ItemCF（基于物品的协同过滤）

根据用户历史行为找到相关物品，再推荐与这些物品相似的候选。电商中“看了又看”“买了又买”是典型使用方式。

Content-Based Recommendation（基于内容的推荐）

利用物品标题、类目、标签、图像等内容特征，匹配用户历史偏好。它能帮助新物品获得推荐机会，但容易把推荐范围限制在用户已有兴趣附近。

MF（Matrix Factorization，矩阵分解）

把稀疏的用户—物品交互矩阵分解为用户向量和物品向量，通过向量内积估计偏好。隐语义向量是从行为中学习得到的，不一定对应人工定义的兴趣标签。

FM（Factorization Machines，因子分解机）

用隐向量内积建模稀疏特征之间的二阶交互。相比只处理用户—物品矩阵的 MF，FM 可以同时接入场景、类目等多字段特征。

DLRM（Deep Learning Recommendation Model，深度学习推荐模型）

DLRM 通常特指 Meta 提出的一类模型架构：类别特征经 Embedding 表示，数值特征经 MLP 处理，再建模特征交互并预测目标。工程中“DLRM”有时也被泛指类似的深度推荐结构，应结合上下文判断。

Cold Start（冷启动）

新用户缺少行为、新物品缺少反馈或新系统缺少历史数据时，协同信号不足的问题。常见缓解方式包括内容特征、热门先验、探索流量和迁移学习。

Popularity Bias（流行度偏差）

热门物品因为获得更多曝光和反馈，模型进一步提高其排序位置，从而形成自我强化。只看点击准确率可能让长尾内容越来越难被发现。

2. 用户、物品与行为数据

User / Item

User 是推荐对象，Item 是被推荐对象。Item 可以是商品、视频、文章、音乐或广告，不一定是实物。

Implicit Feedback（隐式反馈）

点击、播放、停留、加购等自然行为。它数量大但噪声也多，“没有点击”不必然表示不喜欢，可能只是没有看到。

Explicit Feedback（显式反馈）

评分、点赞、点踩、收藏意愿等用户主动表达。它语义更直接，但数据通常更少，也可能受表达偏差影响。

Positive / Negative Sample（正 / 负样本）

正样本是被定义为目标行为的交互，负样本表示未发生目标行为或明确负反馈。曝光未点击常被当成负样本，但其中可能包含位置偏差和展示不足。

Negative Sampling（负采样）

从大量未交互候选中抽取部分负样本训练。均匀采样、热门采样、困难负样本采样会改变模型学到的决策边界。

Feature（特征）

模型用于预测的输入信息，可分为用户特征、物品特征、交叉特征和上下文特征。

Sparse / Dense Feature（稀疏 / 稠密特征）

用户 ID、物品 ID、类目等离散高基数特征通常是稀疏特征，经 Embedding 表查表；年龄、价格、时长等连续值属于稠密特征，常先归一化或分桶。

Context Feature（上下文特征）

描述当前请求环境的特征，例如时间、位置、设备、入口、网络状态和已展示位置。

Cross Feature（交叉特征）

组合多个字段表达联合关系，例如“用户常驻城市 × 商家城市”。显式交叉需要控制组合爆炸，深度模型也可通过网络隐式学习交互。

Embedding（嵌入向量）

把高维稀疏 ID 映射为低维稠密向量。相近向量表示模型认为它们在当前训练目标下具有相似行为模式，并不等同于人类语义完全相同。

Sequence（行为序列）

按时间排列的点击、观看、购买等行为。序列模型会利用兴趣演化、行为间隔和顺序信息，而不只是汇总历史物品集合。

Session（会话）

一段连续访问中的行为集合。会话边界通常按时间间隔或业务事件切分，适合建模短期意图。

Label Leakage（标签泄漏）

训练特征中包含预测时不可获得、或由目标行为之后产生的信息，导致离线指标虚高而线上失效。

3. 多阶段推荐链路

Candidate Generation / Recall（候选生成 / 召回）

从百万或亿级物品池中快速找出数百到数千个候选。召回优先保证相关物品“进得来”，模型需要兼顾速度和覆盖。

Multi-Channel Recall（多路召回）

并行使用 ItemCF、热门、向量、关注关系、地理位置等多个召回通道，再合并去重。不同通道覆盖不同兴趣来源。

Matching（匹配）

衡量用户与候选物品是否相关，通常对应推荐链路中的召回阶段。在工业文献中也常与 Ranking 相对出现。

Two-Tower Model（双塔模型）

用户塔和物品塔分别编码用户与物品，输出向量后通过内积或余弦相似度匹配。物品向量可以离线计算，适合大规模 ANN 召回。

ANN（Approximate Nearest Neighbor，近似最近邻）

在向量库中快速查找与查询向量最相似的一批向量。它允许牺牲少量召回精度来换取更快的检索速度；具体的内存占用取决于索引类型和参数，不能一概认为比精确检索更省内存。

Pre-Ranking（粗排）

用比精排更轻的模型把召回候选进一步压缩。粗排要在效果、延迟和与精排的一致性之间取平衡。

Ranking（精排）

对较小的候选集使用更多特征和更复杂模型，预测点击、转化、时长等目标并形成排序分数。

Re-Ranking（重排）

在精排结果上进行列表级调整，处理多样性、去重、业务规则、频控、公平性和探索等约束。

Retrieval / Ranking / Re-Ranking

三者分别解决“从大池子找候选”“对候选估分排序”“从整张列表角度调整”的问题。阶段越靠后，候选越少，允许使用的计算通常越多。

4. 排序模型与训练目标

特征交叉与 CTR 排序模型

Wide & Deep

由 Wide 线性部分和 Deep 神经网络部分联合组成。Wide 部分擅长记忆已有的特征组合，Deep 部分通过 Embedding 和 MLP 学习未见组合的泛化表示。Wide 部分通常仍依赖人工设计的交叉特征。

DeepFM（Factorization-Machine based Neural Network）

把 FM 与 DNN 组合在同一模型中，并让两部分共享输入和 Embedding。FM 学习一阶与二阶特征交互，DNN 学习更高阶的非线性关系，常用于 CTR、CVR 等概率预估任务。

DCN（Deep & Cross Network）

在 DNN 之外增加 Cross Network，逐层显式构造有界阶数的特征交叉。与完全依赖 MLP 隐式学习交互相比，DCN 对稀疏类别特征的组合关系更有针对性；DCN-V2 是其常见改进版本。

DLRM（Deep Learning Recommendation Model）

先用 Embedding 表示稀疏类别特征，用 MLP 处理稠密特征，再进行特征交互并输出预测分数。DLRM 既指一种推荐模型结构，也经常作为大规模推荐训练与推理的系统基准。

用户兴趣与序列排序模型

DIN（Deep Interest Network，深度兴趣网络）

根据当前候选物品，对用户历史行为进行目标相关的加权聚合。与把全部历史压缩成同一个固定向量相比，DIN 会为不同候选物品生成不同的兴趣表示，常用于电商和广告 CTR 排序。

DIEN（Deep Interest Evolution Network，深度兴趣演化网络）

在 DIN 的目标相关兴趣建模基础上，进一步描述兴趣随行为序列的变化。它使用序列结构提取兴趣状态，通过辅助损失增强兴趣表示，再围绕候选物品建模兴趣演化。

序列与生成式推荐模型

HSTU（Hierarchical Sequential Transduction Units）

面向高基数、非平稳用户行为流设计的序列建模架构。它把推荐重构为序列转导问题，用适配推荐数据的注意力模块处理较长的行为历史，可用于生成式推荐中的检索与排序。HSTU 不是传统的单样本 CTR 模型。

TIGER（Transformer Index for GEnerative Recommenders）

一种生成式召回模型。TIGER 先将物品内容向量量化为由多个离散 Token 组成的 Semantic ID，再用 Transformer 编码用户历史并自回归生成下一个物品的 Semantic ID。它直接生成候选标识，不依赖常规的向量 ANN 检索。

OneRec

用一个端到端生成式模型统一召回与排序。它通过 Encoder-Decoder 编码用户行为并按会话生成推荐结果，还引入稀疏 MoE 扩展模型容量，并通过偏好对齐优化生成列表。OneRec 与传统逐候选计算 pCTR 的精排模型不是同一类方法。

CTR（Click-Through Rate，点击率）

点击次数除以曝光次数：

CTR=点击次数曝光次数\text{CTR}=\frac{\text{点击次数}}{\text{曝光次数}} CTR=曝光次数点击次数​

CTR 模型通常预测 pCTR，即给定用户、物品与上下文后的点击概率。

CVR（Conversion Rate，转化率）

转化次数除以点击次数，转化可以是购买、关注、收藏或下载：

CVR=转化次数点击次数\text{CVR}=\frac{\text{转化次数}}{\text{点击次数}} CVR=点击次数转化次数​

只有点击样本才能观察到后续转化，训练 CVR 模型时要留意样本选择偏差。

CTCVR（Click-Through & Conversion Rate）

从曝光到转化的联合概率，常写作：

p(转化∣曝光)=p(点击∣曝光)⋅p(转化∣点击)p(\text{转化}\mid\text{曝光})=p(\text{点击}\mid\text{曝光})\cdot p(\text{转化}\mid\text{点击}) p(转化∣曝光)=p(点击∣曝光)⋅p(转化∣点击)

Pointwise / Pairwise / Listwise

Pointwise 把每个物品单独预测；Pairwise 学习正负物品的相对顺序；Listwise 直接从列表层面优化排序。三类方法使用的训练信号和目标函数不同。

BCE（Binary Cross-Entropy，二元交叉熵）

CTR 等二分类任务常用的损失：

L=−[ylog⁡p+(1−y)log⁡(1−p)]\mathcal{L}=-\left[y\log p+(1-y)\log(1-p)\right] L=−[ylogp+(1−y)log(1−p)]

其中 yyy 是标签，ppp 是模型预测概率。

Multi-Task Learning（多任务学习）

一个模型同时学习点击、转化、时长等多个目标，通过共享表示利用任务之间的信息。任务冲突、样本量差异和损失权重是常见问题。

Calibration（校准）

预测概率与真实发生频率的一致程度。若一批样本的预测 CTR 为 0.2，理想情况下约 20% 的样本应点击。排序能力好并不保证概率校准好。

Overfitting / Underfitting（过拟合 / 欠拟合）

过拟合指模型在训练数据表现很好、泛化变差；欠拟合指模型连主要规律都没有学到。时间切分验证通常比随机切分更贴近推荐线上环境。

5. 离线评估指标

Precision@K（精确率）

Top-K 推荐中正样本所占比例：

Precision@K=∣Top-K∩正样本∣K\text{Precision@K}=\frac{|\text{Top-K}\cap\text{正样本}|}{K} Precision@K=K∣Top-K∩正样本∣​

Precision 中文也常称“查准率”，不要与分类任务中的 Accuracy（准确率）混为一谈。

Recall@K（召回率）

Top-K 推荐覆盖真实正样本的比例：

Recall@K=∣Top-K∩正样本∣∣正样本∣\text{Recall@K}=\frac{|\text{Top-K}\cap\text{正样本}|}{|\text{正样本}|} Recall@K=∣正样本∣∣Top-K∩正样本∣​

Precision@K 关注推荐出来的结果有多少是相关的，Recall@K 关注全部正样本中有多少进入了 Top-K。

HitRate@K（命中率）

判断 Top-K 中是否至少命中一个正样本，再对用户取平均。它关注“有没有命中”，不区分命中一个还是多个。

AUC（Area Under the ROC Curve）

可解释为随机取一对正负样本时，模型把正样本排在负样本前的概率。AUC 衡量相对排序能力，不直接反映概率是否校准。

GAUC（Group AUC）

先按用户、请求等分组计算 AUC，再按曝光数或样本数加权。它比全局 AUC 更关注组内排序，但只有单一标签的组无法计算普通 AUC。

NDCG@K（Normalized Discounted Cumulative Gain）

同时考虑相关性等级和排序位置，越靠前的命中权重越高，再用理想排序归一化到可比较区间。

MRR（Mean Reciprocal Rank）

取第一个相关结果排名的倒数，再对请求求平均。它特别关注首个命中出现得是否足够靠前。

MAP（Mean Average Precision）

对每个相关物品被命中时的 Precision 求平均，再跨用户或请求取均值，适合存在多个相关结果的排序任务。

Coverage（覆盖率）

推荐结果覆盖的不同物品占候选池的比例，也可定义为用户覆盖。它反映系统是否长期只推荐少数热门内容。

Diversity（多样性）

衡量同一推荐列表中物品之间的差异。多样性过低会让列表重复，过高也可能损害相关性。

Novelty / Serendipity（新颖性 / 惊喜度）

新颖性偏向用户过去较少接触或整体不热门的内容；惊喜度还要求结果与显而易见的推荐不同，同时对用户有用。

6. 在线实验与业务指标

Online A/B Test（在线 A/B 实验）

把用户随机分入实验组和对照组，只改变待验证因素，比较真实业务指标。离线指标用于筛选模型，线上实验才直接反映产品环境中的整体影响。

North Star Metric（北极星指标）

团队长期优化的核心价值指标，例如有效观看时长、成交用户数。它不是越多越好的一串指标，而是用于统一主要目标。

Guardrail Metric（护栏指标）

用于防止主指标改善以牺牲体验或系统稳定性为代价，例如投诉率、退款率、延迟和崩溃率。

Lift（提升）

实验组相对对照组的变化，可以报告绝对提升或相对提升：

相对 Lift=实验组指标−对照组指标对照组指标\text{相对 Lift}=\frac{\text{实验组指标}-\text{对照组指标}}{\text{对照组指标}} 相对 Lift=对照组指标实验组指标−对照组指标​

Statistical Significance（统计显著性）

衡量观察到的差异是否可能由随机波动造成。显著不等于业务价值大，也不等于结果可以不考虑实验设计和多重检验。

Interleaving（交错实验）

把两个排序器的结果混合展示，通过用户对混合列表的偏好快速比较排序质量。它灵敏，但适用指标和产品形态有限。
